05 / PRESENTATION

儀表板接到什麼

純靜態頁面：讀取 replay／live／metrics JSON，更新地圖、推播卡、預警卡、圖表與指標。

原始碼：dashboard/index.html、app.js、style.css
01 / DATA FILES

資料來源檔

儀表板是純靜態頁（Leaflet 地圖 + Chart.js，CDN 載入），不執行模型，只讀 dashboard/data/。啟動：uv run python -m http.server 8000 -d dashboard。

檔案產生者用途
index.jsonfcf replay重播日期清單，填入「資料」下拉選單
replay-YYYYMMDD.jsonfcf replay重播 frames
live.jsonfcf live即時 frames（不進版控）；選「即時」後每 60 秒重新載入
metrics.jsonfcf evaluate「模型評估指標」區

選擇重播時，時間軸預設停在第一個 decision.push 的 frame，沒有則停在起點。

02 / MAP

地圖

  • 切換鈕：「實際車速」顯示 frame.actual；「預測 +30 分」顯示 frame.pred["30"]。
  • 平面與高架在地圖上近乎重疊：高架畫粗線（9px、半透明）在底，平面細線（4px）在上。
  • Tooltip：路線、路段描述、車速；在預測模式且有 prob 時多一行「+30 分壅塞機率 N%」。

03 / CARDS

右側三張卡片

  1. 推播卡 renderPush推播時顯示改道訊息、未入選者訊息（若有），以及情境表：全部訂閱用戶改道（naive 30%）與配額分流（p*）的替代路線預測 TT、相對增加、節省。不推播時顯示中文原因（app.js 自己的 REASON_ZH）。
  2. 壅塞預警卡 renderAlarm依 +15／+30／+60 各一列，列出 frame.alarm[h] 的路段與機率；沒有則顯示「無」。舊資料沒有 alarm 欄位時，提示重新執行 fcf replay。
  3. 路線旅行時間圖國1平面／五楊高架各兩條：實際（實線）與 +30 預測（虛線），垂直虛線標示目前 frame。
04 / METRICS

評估指標區

讀 data/metrics.json：訓練／測試期間、車速 MAE（最小值標 better）、壅塞前預警（每個時距 × 子集各兩列：回歸模型、分類器）、壅塞起點提前量（回歸模型、分類器）、分流模擬。缺檔顯示「尚無評估指標：請先執行 uv run fcf evaluate」；舊版 metrics（沒有 classifier 欄位）無法顯示，需重新評估。
