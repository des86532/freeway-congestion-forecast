01 / INPUT & PREPARATION

資料怎麼進來

從高公局 M05A 原始檔到連續的 5 分鐘 × 18 路段網格：節流、解析、補缺、日曆與路段定義。

原始碼：http.py、tdcs.py、dataset.py、calendar.py、static.py、corridor.py
01 / HTTP

唯一的對外出口：http.py

所有對 tisvcloud.freeway.gov.tw 的請求都必須經過 fetch(url, min_interval=41.0)。

  • SSL 修正：關閉 VERIFY_X509_STRICT。Python 3.13 預設 strict 會因「Missing Subject Key Identifier」驗證失敗。
  • 節流：高公局要求同一 host 請求間隔大於 40 秒，預設 41 秒。只對該 host 生效；DGPA 日曆不節流（min_interval=0）。
  • 重試：最多 3 次；HTTP 404 不重試；逾時、連線、SSL 錯誤會重試，每次重試前同樣節流。
02 / PARSE

M05A 解析與下載：tdcs.py

M05A 是無表頭 CSV，欄位依序為：

TimeStamp, GantryFrom, GantryTo, VehicleType, Speed, Volume 2026/10/01 07:55,01F0492N,01F0467N,31,25,185
  • 只取 VehicleType == "31"（小客車）；路段 ID = GantryFrom-GantryTo，不在走廊 18 段內者略過。
  • speed <= 0 → NaN（M05A 以 0 表示無資料）；volume < 0 → NaN；volume == 0 合法，保留。
  • fetch-history 逐日下載整日 tar.gz；已存在且可讀者跳過，因此可中斷續傳；單日失敗只記錄，最後列出失敗日期。
03 / GRID

建立完整網格：dataset.py

  1. 去重同一 (ts, seg) 保留最後一筆。
  2. 補齊網格對資料中出現的每一天，建立 288 個 5 分鐘時間點 × 18 路段；缺漏的點為 NaN。
  3. 補缺口speed 依路段 ffill(limit=3)，最多往後填 15 分鐘；volume 不填補。
  4. 加上日型is_holiday（int8），速度與流量轉 float32，輸出 data/processed/corridor.parquet。
兩處必須一致：live.py 的 to_df 對滾動資料使用同樣的規則（去重、ffill(limit=3)、is_holiday）。改其中一處就要同步另一處。
為什麼先補網格？如果時間中間有缺口，直接對列做 shift 可能把「前一筆」誤當成「前 5 分鐘」。連續時間軸讓 lag 與未來目標才對得準（features.to_wide 也會再補一次缺日）。
04 / STATIC

辦公日曆與路段幾何

  • calendar.py：讀 data/static/calendar_2026.csv（行政院人事行政總處），是否放假 == 2 視為放假；日曆未涵蓋（含檔案不存在）時以週六日判定。
  • static.py：從 ETagPair.xml 取出走廊 18 段的 WKT LINESTRING，轉成 [lat, lon]；有任何路段缺幾何就不寫檔。幾何只給儀表板畫地圖，與模型無關。
  • corridor.py：18 個路段 ID、距離、順序的唯一來源；neighbors() 回傳同路線的上、下游路段。
