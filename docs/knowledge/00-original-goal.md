# 00 原始目的

本文件記錄專案發起時的「提案說明」原文，作為判斷範圍與優先順序的依據；並對照 MVP 目前實際做到的部分。現況細節以 01–07 與程式碼為準。

## 原始提案說明（原文）

> 現今上下班尖峰時段經常發生交通壅塞，駕駛人往往在抵達壅塞路段後才得知路況，不僅浪費通勤時間，也增加油耗與碳排放。本提案透過 AI 結合道路監視器影像、即時車流資料、歷史交通數據、天氣及事故資訊，建立交通壅塞預測模型，於壅塞形成前即分析未來車流變化，提前預警可能壅塞的路段。
>
> 當系統預測特定路段將發生壅塞時，會透過導航系統、手機 App、LINE 官方帳號或道路資訊看板，即時向用路人推播替代路線及預估可節省的通勤時間，協助駕駛提前改道，分散車流，降低整體道路負載。同時，系統可提供交通管理單位即時分析資訊，作為號誌調整及交通疏導的重要依據。
>
> 本提案的創新亮點在於由傳統「壅塞後通知」提升為「壅塞前預測」，運用 AI 主動分析並預先分流，不僅提升民眾通勤效率，也有助於降低交通壅塞、減少碳排放，打造更智慧、更安全的交通管理模式。

## 原始目標 vs MVP 現況

| 原始目標 | MVP 現況 | 詳見 |
|---|---|---|
| 壅塞形成前預測、提前預警 | ✅ 預測 15／30／60 分鐘後各路段車速（迴歸），另有壅塞機率分類器做預警 | [03](03-features-and-models.md)、[04](04-evaluation.md) |
| 即時車流資料、歷史交通數據 | ✅ 高公局 M05A（5 分鐘站間中位數車速、流量，小客車）；歷史檔訓練、近期檔即時輪詢 | [02](02-data-pipeline.md)、[06](06-replay-live-notify.md) |
| 道路監視器影像（CCTV）、天氣、事故 | ❌ 未納入。事故、天氣目前只有即時 XML，沒有可回測的歷史資料（見 `docs/proposal.md` §4），列為擴充 | – |
| 推播替代路線與預估節省時間 | ✅ 訊息含最差路段、預測車速、建議路線、預估節省分鐘 | [05](05-diversion.md) |
| 推播管道：導航、App、LINE、道路資訊看板 | 部分：只實作 LINE（單一收件人）；導航業者／App／CMS 看板未實作 | [06](06-replay-live-notify.md) |
| 分散車流、降低整體道路負載 | ✅ 並延伸為「系統最佳配額」：以 BPR 估算替代道路負載，限制改道比例 `p*`，避免所有人改走同一條路。用戶分組函式 `select_for_reroute` 已實作，但尚未接上推播 | [05](05-diversion.md) |
| 提供交通管理單位即時分析（號誌、疏導） | ❌ 未實作；儀表板只呈現預測、決策與評估 | [07](07-dashboard.md) |
| 減少油耗與碳排 | 僅定性說明；系統車輛時間節省為模型估算（車輛小時），未換算碳排（見 `docs/proposal.md` §9） | [04](04-evaluation.md) |
