PROJECT LOGIC / 00

從壅塞預測，到有配額的分流

這個專案不是只找「個人最快路線」。它先預測兩條平行路線的壅塞，再估算改道對替代道路造成的負載，最後決定是否推播、以及建議多少比例的用戶改道。

資料粒度：5 分鐘走廊：18 路段 / 2 路線訓練 2026-04-01～07-31測試 2026-08-01～09-06
00 / ORIGINAL GOAL

原始目的

尖峰時段駕駛人往往抵達壅塞路段才知道路況。提案的核心是把傳統「壅塞後通知」提升為「壅塞前預測」：預先判斷哪些路段即將壅塞，向用路人推播替代路線與預估節省時間，提前分散車流，並提供交通管理單位分析資訊。原文收錄於 docs/knowledge/00-original-goal.md。

03 / WHAT IT DOES NOT CLAIM

現況與限制

  • 只涵蓋湖口到高公局北上走廊；事故、施工、天氣、CCTV 未納入。
  • 重播以資料時間戳為「現在」，沒有模擬高公局檔案發布延遲（實測約 5–7 分鐘）。
  • 旅行時間是同一時刻車速的路段加總，不是時變行進模擬。
  • 分流效益由 BPR 模型與固定 30% 訂閱比例估算，不是實際用戶實驗。
  • 分類器 Recall 提高的代價是 Precision 下降（誤報增加），詳見評估。
  • select_for_reroute 已實作但未接上推播；live --push 只把改道訊息送給單一 LINE 收件人。
